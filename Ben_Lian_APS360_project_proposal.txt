Introduction
Modern video games are increasingly viewed as more than entertainment: they are structured,
data-rich systems where learning algorithms can be trained, evaluated, and deployed at scale. As
DeepMind notes, “Games have been used for decades as an important way to test and evaluate
the performance of artificial intelligence systems.” ( 1) This project focuses on the rhythm game
osu!( 2) and aims to build a deep learning “map reader” that segments a beatmap (3) into labeled
patterns. Further application of a successful model can be applied to support beatmap difficulty
calculation, which helps maintain the healthiness of the game. Deep learning is a reasonable approach
because these patterns are sequential and context-dependent: the same local spacing can represent
different gameplay intent depending on surrounding rhythm, angle changes, and slider velocity,
making heuristics brittle across different beatmaps.
Illustration
Figure 1: End-to-end pipeline for the proposed .osu map reader. Beatmaps are parsed into feature
sequences, heuristics generate Level-1 pseudo-labels, and manual review refines and add Level-2
subtypes. A Transformer sequence model is trained using the corrected labels as ground truth (via
supervised loss), and is then used to infer object pattern labels on other beatmaps.
Background & Related Work
Recent works motivate learning-based approaches for understanding and evaluating structure in games
and, more specifically, rhythm-game charts. TaikoNation targetspatterning-focusedchart generation,
showing that neural models can learn and reproduce recurring chart motifs ( 4). Mania Archetype
also studies the generation of rhythm-game charts, reinforcing the idea that chart structure can be

modeled in a way that reflects player experience (5). Osu2MIR demonstrates that the information
from osu-derived beatmaps can be repurposed into a research dataset (6). More broadly, the PCGML
literature surveys deep learning methods for procedural game content, positioning rhythm-game
charts as a viable domain for learned structure in game design artifacts (7). In terms of ML used to
evaluate game-related data, esports analytics has applied machine learning to infer results from game
signals (8). These works collectively motivate the goal of learning an interpretable pattern labeling
of .osu hit-object sequences (Level-1 and Level-2) rather than only producing coarse difficulty
summaries.
Data Processing
Beatmaps that contain the .osu files can be obtained from osu!’s official beatmap listing (9). .osu
files will be parsed according to the structure of .osu files (10). A preprocess program will parse the
two relevant sections for this project: [TimingPoints] and [HitObjects]. To parse, subsequent
lines are read until the next header line beginning with [ or end-of-file; by iterating through the file
line-by-line (e.g., for line in f: ) and using the read and write function ( 11) will be effective.
Parsed data will be stored as feature.file (.csv or .txt)
After creating feature.file, the objects will receive a pseudo label from a heuristic program by
computing the beat-normalized spatiotemporal relationships between objects (e.g., ∆b, ∆x, ∆y,
normalized spacing d/R, and turn-angle features). These quantities, together with a Level-1 label,
will be appended to each object entry. They will then be manually corrected and labeled for Level-2
subtypes. The resulting corrected dataset is split into training/validation/test subsets.
The official definition of patterns are incomplete on the osu! wiki (12). But this Youtube video (13)
provides the very basic definitions. This project will have the following categories:
Level-1: Jumps, Streams, Sliders, Filler
Level-2: Jump Aim, Awkward Aim, Flow Aim, Accelerating Flow Aim, Slider Aim, Linear Aim
Architecture
Transformer encoderwill be used as the main model. Intuitively, a Transformer processes a
sequence by usingself-attention, which allows the prediction at one hit object to depend on other
nearby or distant hit objects in the same clip. This is useful because osu! patterns are defined by
relationships across multiple notes. The Transformer outputs a representation for each hit object, and
then a small classification layer converts these representations into pattern labels.
There are two levels of output implementation: (1) a simple Level-1 classifier, and (2) an Level-2
classifier that brings the label down to subtypes within each Level-1 category. Exact details such as
the number of layers, hidden dimension, and attention heads will be chosen experimentally during
implementation.
Baseline Model
Currently, osu! has a heuristic difficulty evaluation system that assess the notes’ spacing and speed,
and provides it with a numerical rating, while this project does not have a scope large enough to train
a model that provide something at that level of complexity, this existing heuristic can be used as a
baseline when the neural network receives further development. This project is merely a baseline for
something bigger.
Ethical Considerations
Beatmaps may include copyrighted assets (audio/backgrounds), so the pipeline will use only .osu
text and derived numeric features, and will not share media files. Since beatmaps are community-
created, the project will follow osu!’s content usage permissions ( 14). Finally, pattern labels are
subjective (e.g., whether the aim is awkward or not), so the annotations may reflect personal bias and
the model may inherit it, so labeling criteria and failure cases will be documented; labeling rules and
outputs will be presented as descriptive rather than authoritative.
